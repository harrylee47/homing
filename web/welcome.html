Homing

卡留在家，号跟着你走。

新 iPhone 只有 eSIM，那张用了十年、绑着银行和支付宝的实体卡插不进去；想转 eSIM， 多半要本人回归属地营业厅办——而你在八千公里外。于是国内号码被钉在一台旧安卓机上： 背着走，包里多一台要单独充电的手机；放家里，验证码就收不到。

Homing 是第三种：那台手机留在家里的插座上，它收到的短信、来电、App 通知， 几秒之内响在你身边这台手机上——验证码长按就复制，不用打开任何 App，也不用叫醒任何人。

开源 AGPL-3.0 不需要公网 IP 一台闲置安卓机就够

Homing 取自 homing pigeon（信鸽）：一只待在老家的鸽子，把消息带到你身边。

新手机没有卡槽

美版 iPhone 从 14 起取消了实体卡槽，iPhone Air 更是全球只有 eSIM。换机那天你才发现，那张绑着银行、支付宝和一堆账号的卡，在新手机上没地方插。

转 eSIM 要本人回去办

实体卡转 eSIM 要走实名流程，机型、套餐、归属地各有条件，多数情况要本人到营业厅。人在国外，客服的标准答复是「请到归属地营业厅办理」。

60 秒，转不到第二手

银行和支付类验证码多数 60 秒过期。对方看到消息、翻到那条短信、截图发给你，你再照着输——按下确认时页面已经提示「验证码已失效」。不是没人帮你，是来不及。

你的白天，他们的凌晨

时差是硬的。你办事的时间正好是家里人睡着的时间，而转账、改绑、抢票这些事往往排不到明天。

麻烦人是有额度的

登录要、转账要、改绑要、挂号要，一个月好几次。次数多了你会开始掂量「这事值不值得再麻烦一次」，于是该办的一拖再拖——这才是最贵的那部分。

代收的人，顺便全看见了

让家里人转发，等于把银行验证码、余额变动、你正在办什么事一并给了对方。多半没人会介意，但这件事本来不必让任何人经手。

几种常见办法都不太行：国际漫游贵，而且不是每家运营商都转发验证码； 让家里人转发，等转到手多半已经失效；接码平台等于把号码交给陌生人。

它是怎么工作的

1 · 家里的旧手机

插着国内卡、插着充电器、连着 WiFi。装一个 App，扫一次码，之后就不用再碰它。

2 · 这台服务器

手机主动连上来，不需要公网 IP、不用内网穿透。收到的消息按你写的规则分发。

3 · 你身边的手机

验证码出现在通知栏，长按即复制。也可以发到 Telegram 或你自己的接口。

它也替你盯着那台手机

掉线就告诉你

插头被拔、WiFi 换了密码、被系统清后台——这些平时发现不了， 都是在你急着要验证码的那一刻才暴露。它掉线超过阈值会直接推给你，电量太低也会。 告警走的是不经过那台手机的通道——用掉线的设备通知你它掉线了，没有意义。

按时发保号短信

长期零消费会停机，停久了号被回收卖给下一个人—— 那时他手机上收到的，是你银行和支付账户的验证码。这才是保号真正的理由。 保号任务按排期自己发，双卡的话一张卡一个任务，不用每月托人记着。

联系不上它的时候，还能问它

服务端连不上那台手机时，可以直接给它发一条带口令的短信， 问电量、信号、网络、位置。这条路完全在手机本地跑完，一步都不经过服务器—— 「手机联不上服务端了，我还想知道它怎么了」，这个功能的全部意义在此。

能力是刻意做窄的：只能查，不能发短信。口令泄漏最多让人知道这台手机还活着。

五步走完

1注册账号

向邀请你的人要一个邀请码，打开注册页填上。 注册前会让你读一份风险声明——请真的读完，那不是免责套话。

2下载并安装 App

装在家里那台插着国内卡的安卓机上，见上面的下载区。 系统提示「来自未知来源」时，在弹出的设置里允许浏览器安装应用。

3把手机和账号配上对

在控制台的「设备」页点生成配对码，用 App 里的「扫码配对」对准那个二维码。

配对前 App 会显示要连到哪台服务器，请看清楚再确认—— 扫错一个码，这台手机之后收到的每一条验证码都会发给别人。

4给权限、让它别被杀掉

短信、通话记录、通知读取三项权限要给全；再把这个 App 加进电池优化白名单。 不同手机叫法不一样，一般在「电池 → 后台运行 / 自启动」，小米叫「省电策略 → 无限制」， 华为叫「应用启动管理 → 手动管理」。

少给一项，对应的那类消息就静悄悄地收不到——不会报错，也不会有提示。

5配推送渠道，然后按测试

在总览页点「管理渠道」（或 设置 → 通知渠道 → 管理），加一个 Bark 或 Telegram。 具体步骤见下一节。

一定要点那个测试按钮。渠道配错是最常见的故障， 而它的表现是「什么都没发生」——你不会收到任何错误提示，只是验证码再也不来了。

测通了再去规则页点「写入建议规则」，验证码才会穿透专注模式、广告才会只归档。

在哪儿看，怎么收到

每个入口解决的问题不一样，配一个就能用，多配几个互不冲突。

网页 —— 全功能的那一个，建议装到主屏幕

历史消息、按号码归成的对话、通话记录、发送短信、规则、设备状态， 全都在这里。推送渠道只是「把某几条消息送到你眼前」， 要翻、要搜、要改配置，都得回到网页。

  1. 用手机浏览器打开这台网关，登录。
  2. iPhone：Safari 底部的分享键 → 往下找「添加到主屏幕」 → 添加。 必须用 Safari，微信和 Chrome 里没有这个选项。
  3. 安卓：Chrome 右上角 ⋮ → 「安装应用」或「添加到主屏幕」。
  4. 从主屏图标打开，登录时勾上「保持登录 30 天」。

装上之后是全屏、没有地址栏，和一个 App 没什么差别。 控制台的设置页里有一张卡会按你的手机给出对应的步骤。

两件事先说清楚：主屏 App 和浏览器是两个独立的存储空间， 浏览器里的登录状态带不过去，要再登一次（所以才让你勾「保持登录 30 天」）。 另外它不负责推送——通知仍然靠下面那几个渠道， iPhone 上通知点进去也只会开 Safari，不会进主屏 App。

Bark —— iPhone 上收验证码的首选

只有 iPhone 有。安卓请看隔壁那格的 ntfy， 做的是同一件事。

验证码直接显示在锁屏上，长按即复制，不用打开任何 App。 这台服务器自带一个 Bark 服务端，不用另外部署、也不经过第三方。

  1. App Store 搜 Bark 装上。
  2. 打开控制台 → 总览页点「管理渠道」 → 类型选 Bark。 表单顶上有一块灰底说明，里面是服务器二维码和服务器地址 （形如 https://你的域名/bark）。
  3. 回到 Bark App，切到底部的「服务器」页，点右上角的 ＋。 注意这一步加的是服务器——不是「添加 Bark」，也不是加推送。 扫上一步那个码，或者手动把服务器地址填进去。
  4. 加完服务器后回 Bark 首页，上面有一条示例推送地址，形如 https://你的域名/bark/xxxxxxxx/推送内容。 中间那段就是设备 Key——Bark 首页不会单独把它列出来，只能从这条地址里认。
  5. 把整条地址复制，粘进控制台表单里的「粘贴整条推送地址」框。 系统会自己认出里面的 Key 填好，不用你去数是哪一段。
  6. 点「测试」。手机响了就成了。

第一次绑定要把「开放档位」临时调成完全开放，绑完调回「允许推送」。 这个开关只有管理员能改——如果你是被邀请进来的成员，这一步要找管理员开一下。

ntfy —— 安卓上收验证码的首选

和 Bark 做的是同一件事：验证码显示在通知栏，通知上直接有一个 「复制验证码」按钮，点一下进剪贴板，不用打开任何 App。开源、可自建， 没有封号这回事。

  1. 应用商店（或 F-Droid）装 ntfy。
  2. 控制台 → 总览「管理渠道」 → 类型选 ntfy → 点「随机生成」得到一个主题名 → 保存。
  3. 回到 ntfy App，点 + 订阅主题：主题名填刚才那个， 服务器保持默认（https://ntfy.sh）或填你自建的地址。
  4. 回控制台点「测试」。手机响了就成了。

主题名就是这条通道的口令。在公共实例上， 任何知道主题名的人都能订阅它，没有别的门——而这里流的是你的银行验证码。 所以务必用那个「随机生成」按钮，别自己起「sms」「yzm」这种； 更稳的做法是自己搭一个 ntfy，或者用受保护的主题加访问令牌。

iOS 上也有 ntfy 客户端，但那个「复制」按钮 官方只保证安卓 App 与网页版有。iPhone 还是用 Bark。

Telegram —— 聊天式，安卓电脑都能收

正文是打码的（spoiler），点一下才显示。 这是为了避免 Bot 被封，不是为了防人偷看——内容仍然明文经过 Telegram 的服务器， 并长期留在你的聊天记录里。

  1. 在 Telegram 里搜 @BotFather（认准带蓝色对勾那个），发一条 /newbot。
  2. 它先问你 Bot 的显示名（随便起，比如 我的网关）， 再问用户名——这个必须全局唯一且以 bot 结尾，比如 harry_homing_bot。
  3. 起好之后它回一段话，里面有一行很长的 token，形如 8123456789:AAH...。整行复制下来，这就是 Bot Token。
  4. 先去给你的 Bot 发一条 /start。 点它回复里那个 t.me/你的bot名 链接进去，点底部的「开始 / START」。 这一步不做，下一步一定读不到你。
  5. 控制台 → 总览「管理渠道」 → 类型选 Telegram → 把 token 粘进「Bot Token」。
  6. 点「自动获取 Chat ID」，它会把这个 Bot 最近对话过的人列出来，点你自己那一条即可 ——不需要再去找 @userinfobot。然后保存、点「测试」。

一人一个 Bot。两个人共用同一个 token，推送不受影响（各发各的 chat）， 但 Bot 命令会互相抢：Telegram 只允许一个程序拉取一个 Bot 的消息， 两边会随机丢命令，而且没有任何错误提示。要在这台网关上用 /recent 这类命令，就各自去 @BotFather 建一个。

还有一条顺序坑：渠道一旦保存并启用，最晚一分钟后「自动获取 Chat ID」就用不了了 （Bot 已经被网关接管）。所以正确顺序是：填 token → 发 /start → 点自动获取 → 选中 → 再保存。 事后要改 Chat ID，先把渠道停用、等约一分钟再回来点。

Webhook —— 其它一切

把消息以结构化 JSON POST 到你指定的地址。 企业微信机器人、钉钉机器人、飞书机器人，或者你自己的服务、写进数据库， 都由你自己决定。上面几种满足不了的场景都走这里。

  1. 控制台 → 总览「管理渠道」 → 类型选 Webhook。
  2. 填目标地址，必须是 https。
  3. 点「测试」，确认你那边真的收到了。

内网地址会被拒绝（127.0.0.1、192.168.x、169.254.x 这类）。 这是防 SSRF 的硬限制：一个能让服务器往任意地址发请求的接口，等于把内网借给了别人。 管理员可以对自己的渠道放开这条。

两步验证

可选，但建议开 —— 怎么开、认证器用哪个

开了之后登录要多输一次认证器 App 上的 6 位动态码。 就这一处差别：口令规则、登录保持时长、找回口令的能力，开不开都一样。

手机上装 Google Authenticator、Microsoft Authenticator、1Password， 或者直接用 iOS 自带的「密码」App 都行。在控制台「设置 → 两步验证 → 开启」扫码， 再输一次它显示的 6 位数字即可。

忘了口令有两条路：让系统把找回码发到你配好的推送渠道， 或者直接用认证器上的动态码。两样都没有的话，只能请管理员帮你重置。

关于安全，说实话

这台服务器会存下你手机收到的全部短信，包括银行验证码。

数据在数据库里是加密的（AES-256-GCM），但密钥就在同一台服务器上。 加密挡得住的是「数据库文件被拷走」，挡不住能登上这台服务器的人。

而且服务端必须把正文解开才能判断这是不是验证码、匹配你的规则、拼出推送内容。 所以它做不到端到端加密，也没有「运营者看不到你的短信」这回事—— 任何这类工具声称自己看不见，要么在骗你，要么它根本没在帮你转发内容。

能做到的是：每个账号在控制台里只能看到自己的数据，管理员也读不到别人的消息 （这是写在代码里、有测试盯着的应用层隔离，不是密码学隔离）；推给 Telegram 的正文是打码的； 日志里从不打印正文和验证码。

不放心的话，自己部署一份。项目是开源的，装完这台机器就是你自己的， 谁也不用信。

不做的事

不做接码平台、不做多卡批量管理、不改主叫号码、不做语音中继。 这是个人自用的工具，请自持 SIM 卡、自持设备，并遵守当地法律。

也不保证不漏报。手机没电、断网、被系统杀掉、运营商延迟—— 任何一环都可能让一条短信迟到或收不到。别把它当成唯一的接收手段，尤其是涉及钱的操作。
